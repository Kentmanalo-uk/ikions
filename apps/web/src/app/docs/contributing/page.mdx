# Contributing

Ikions grows in reviewed batches. Every icon goes through the same design rules and automated pipeline, and both variants ship together or not at all.

## Design rules

The full specification lives in `docs/icon-design-spec.md` in the repository. In short:

- **Grid:** 24 × 24 artboard, 20 × 20 live area, keylines for square, circle, portrait and landscape shapes.
- **Outline:** 1.75 stroke, round caps and joins, `currentColor`, no fills except small solid accents.
- **Filled:** a separate silhouette sized to the outline's outer edge, with real cutouts (even-odd holes 1.5–2 units wide) instead of filled outlines.
- **Character:** soft corner radii that scale with shape size, breathing gaps between primary and secondary parts, calm detail.
- **Originality:** draw from the object itself. Never trace or adapt artwork from another icon library.

## Source layout

```text
assets/source/<name>/
  outline.svg
  filled.svg
  meta.json
```

```json
{
  "name": "camera",
  "title": "Camera",
  "category": "media",
  "description": "Capture photos or open a camera interface.",
  "tags": ["photo", "picture", "capture"],
  "aliases": ["photography", "take-picture"],
  "variants": ["outline", "filled"],
  "added": "0.1.0"
}
```

## Pipeline

```bash
pnpm icons:validate   # schema, SVG safety and geometry checks
pnpm icons:sheet      # render review sheets at 16–32 px, light and dark
pnpm icons:build      # optimise and generate every package
pnpm test             # unit, package and rendering tests
```

The validator rejects scripts, external references, raster images, ids, transforms, hard-coded colours, invalid path data, geometry outside the artboard, missing variants, unknown categories and duplicate names or aliases. The optimiser is checked by a test that renders every icon before and after optimisation and compares the pixels.

## Submitting icons

1. Open an issue describing the concept and where it is used.
2. Draw both variants following the specification and add `meta.json`.
3. Run the four commands above and attach the review sheets to your pull request.
4. Confirm in the pull request that you created the artwork yourself (or have the right to contribute it) and that it is not derived from another icon set.

Maintainers review new icons at 16 px next to their category neighbours before merging. Planned icons are never listed as published until they pass this process.
